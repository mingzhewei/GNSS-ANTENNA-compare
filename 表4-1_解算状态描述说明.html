② 这张表是什么：sol stat 是解算引擎对当前这一历元解算结果的健康度标注，逐历元上报。它不是定位精度的档位（那是表 4-2 pos type 的职责），而是回答：“这次算出来的解能不能用？不能用的原因是什么？”

③ 与 OEM6 的差异（如实说明）：OEM6 时代 10/11/14–17 曾有定义（DELTA_POS、NEGATIVE_VAR、INS_INACTIVE 等），但 UG016、OEM7 v11 手册与 NovAtel 在线文档均将这些值列为预留。本文以 UG016 协议与 OEM7 v11 手册为准。PM

1. 核心结论（官方原文）

“只有当解算状态为 SOL_COMPUTED 时，输出的解才应被视为有效。”
原文：The output solution should be considered valid only when the solution status reports SOL_COMPUTED. N

版本说明：该句出自 NovAtel 在线文档（较新版本）【N】；本地 OEM7 v11 手册 Table 73 未收录此句，但其 FIX 命令完整性检查流程（§2.47，P163）体现了同一原则——只有通过测量验证的解才会被标记 SOL_COMPUTED【M】。

3. 分组详解（进入/退出条件均有出处）

Ⓐ 有效解：SOL_COMPUTED(0)

官方定义
Solution computed——完全解算。NovAtel 在线文档明确：只有 sol stat = SOL_COMPUTED 时，输出解才应视为有效。PMN
进入条件
解算收敛且协方差、距离检验、方差、残差等质量检查全部通过。M
退出条件
任一质量检查失败（转入对应原因码），或观测量不足/不收敛/矩阵奇异（转入解算失败码）。M

Ⓑ 启动与解算失败：COLD_START(6) / INSUFFICIENT_OBS(1) / NO_CONVERGENCE(2) / SINGULARITY(3)

官方定义
COLD_START：冷启动后尚未收敛（Not yet converged from cold start）；INSUFFICIENT_OBS：观测量不足；NO_CONVERGENCE：不收敛；SINGULARITY：参数矩阵奇异。PM
进入条件
COLD_START：冷启动（无先验位置/星历）后的初始收敛阶段；INSUFFICIENT_OBS：可用观测不足——PVT 解算含 4 个未知量（纬度、经度、高程、接收机钟差，OEM7 P429 同述），故定位至少需 4 颗卫星；NO_CONVERGENCE：迭代未收敛；SINGULARITY：参数矩阵奇异。PMT
退出条件
逐历元判定：COLD_START 收敛完成后转 SOL_COMPUTED；卫星数/几何恢复、迭代收敛、矩阵条件恢复后，均自动回到 SOL_COMPUTED。M
典型场景
上电头几秒依次出现 COLD_START →（可能闪一下 INSUFFICIENT_OBS）→ SOL_COMPUTED，属正常启动序列。

Ⓒ 质量门限拒绝：COV_TRACE(4) / TEST_DIST(5) / V_H_LIMIT(7) / VARIANCE(8) / RESIDUALS(9) / INTEGRITY_WARNING(13)

官方定义
解算完成但未通过某项质量检验：协方差迹 >1000 m；距离检验 >10 km（最多拒绝 3 次）；高度或速度超出口管制限值；方差超限；残差过大；残差大到定位不可靠。PM
进入条件
对应检验项超限。其中 V_H_LIMIT 的限值源自出口管制：行业公开记载的 COCOM 限值为高度约 18 km、速度约 1000 节（515 m/s）。PMC
退出条件
对应指标回落到门限内即恢复 SOL_COMPUTED（逐历元判定）；TEST_DIST 按官方原文“最多拒绝 3 次”。M
典型场景
遮挡/多径/干扰导致解质量恶化时，日志中会在这几个码之间切换；干扰消失即回 SOL_COMPUTED。RESIDUALS/INTEGRITY_WARNING 常见于强多径或粗差观测。

Ⓓ FIX 命令验证：PENDING(18) / INVALID_FIX(19)（含 INTEGRITY_WARNING 关联）

官方定义
输入 FIX 位置命令后，接收机自行解算位置，由完整性监控（integrity monitor）对固定坐标做误差检查，并按结果标记状态。OEM7 §2.47（P163）记载四级判定：
① SOL_COMPUTED：输入位置已被测量确认；② PENDING：可用测量不足以确认输入位置；③ INTEGRITY_WARNING：一级错误——固定位置偏差约 25–50 m；④ INVALID_FIX：二级错误——固定位置严重偏差。NovAtel 在线新版补充：PPP seed 验证期间也会触发 PENDING。MN
进入条件
① 用户输入 FIX POSITION 命令；② PPP seed 验证。PMN
退出条件
验证需要跟踪 ≥2 颗卫星V：正常上电仅持续数秒即完成验证；若天线遮挡/未连接且已输入 FIX 命令，PENDING 将无限持续PM。验证通过 → SOL_COMPUTED（此时 pos type = FIXEDPOS）；验证失败 → INTEGRITY_WARNING / INVALID_FIX；修正坐标重新输入后再次验证。M
重要后果
被标记 INTEGRITY_WARNING / INVALID_FIX 的错误固定位置会停止差分改正与 RTK 测量的输出，并可能影响时钟控制（clock steering）与卫星信号搜索；该检查可用 RAIMMODE 命令关闭。M
使用建议
FIX POSITION 输入坐标建议精确到几米以内（跟踪 5–6 颗星的单点定位即可达到）；FIX POSITION 仅应用于基站——对流动站施加会使其退出 RTK 模式转为固定位置模式，且不会加速模糊度固定。M
典型场景
基站架设：输入已知点坐标 → 几秒 PENDING → SOL_COMPUTED + FIXEDPOS。若长期停在 PENDING，先查天线；若变 INTEGRITY_WARNING/INVALID_FIX，说明输入坐标与实测相差过大。

Ⓔ 配置类：UNAUTHORIZED(20) / INVALID_RATE(22)

官方定义
UNAUTHORIZED：定位类型未经授权；INVALID_RATE：此解决方案类型不支持所选的输出速率。PM
进入条件
请求了设备授权之外的定位类型；或输出速率超出该解算类型支持范围（OEM7 P430 记载最大输出率：RTK 100 Hz、伪距 100 Hz、GLIDE/PDP 20 Hz、PPP 20 Hz）。PM
退出条件
更正配置/授权、或降低输出速率后恢复。属配置问题，不参与动态流转。M
