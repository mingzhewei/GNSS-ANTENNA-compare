4. 分组详解：每一组“怎么进入、怎么退出、什么时候出现”

⓪ 无解与用户固定：NONE(0) / FIXEDPOS(1) / FIXEDHEIGHT(2) / DOPPLER_VELOCITY(8)

含义
NONE：接收机当前给不出位置（上电初期、卫星数不足、解不收敛）。FIXEDPOS/FIXEDHEIGHT：用户通过 FIX 命令把位置或高程人工固定——OEM7 注明也可由位置平均（position averaging）产生【M P434】；基站模式的标准用法。DOPPLER_VELOCITY：观测不足以定位，但仍可用瞬时多普勒给出速度（多出现在 BESTGNSSVEL 的 vel type 字段）。
进入条件
NONE：上电/复位初始、跟踪卫星 <4 颗、天线断开或被完全遮挡、强干扰导致失锁。FIXEDPOS/FIXEDHEIGHT：用户执行 FIX POSITION / FIX HEIGHT / FIX AUTO，或位置平均完成【M】。OEM7 使用建议：FIX POSITION 坐标应精确到几米以内（跟踪 5–6 颗星的单点即可），仅用于基站——对流动站施加会退出 RTK 模式，且不加速模糊度固定【M §2.47 P163】。DOPPLER_VELOCITY：可用卫星不足以定位但尚可测速。
退出条件
NONE：锁定 ≥4 颗星且伪距解收敛 → SINGLE。FIXEDPOS/FIXEDHEIGHT：执行 FIX NONE 解除固定或重启 → 回到正常解算流程【M §2.47 FIX 类型 NONE=Unfix】。DOPPLER_VELOCITY：观测恢复到可定位 → SINGLE；进一步恶化 → NONE。
典型场景
冷启动头几秒输出 NONE；基站架设后 FIXEDPOS 长期保持；隧道内短时可能只剩 DOPPLER_VELOCITY 速度输出。

① 伪距类：SINGLE(16) / PSRDIFF(17) / WAAS(18) / PROPAGATED(19)

含义
都只用码伪距（不用载波相位），是一切定位的“地基”。SINGLE=无增强；PSRDIFF=本地码差分（DGPS，RTCM 改正数）；WAAS=星基增强（SBAS 地球静止卫星播发改正）；PROPAGATED=观测暂时没了，卡尔曼滤波按运动模型外推。
进入条件
SINGLE：≥4 星、伪距残差收敛、无任何差分改正。PSRDIFF：在 SINGLE 基础上收到有效 RTCM 码差分改正且差分龄期未超限。WAAS：收到 SBAS 星基改正。PROPAGATED：原已定位，观测突然中断但中断时间仍在滤波允许外推窗口内。
退出条件
SINGLE：失锁/<4 星 → NONE；收到码差分 → PSRDIFF；收到 SBAS → WAAS；RTK 载波可用 → 浮点类。PSRDIFF：改正龄期超 PSRDIFFTIMEOUT（默认 300 s，范围 2–1000 s；RTCA SCAT-I 标准建议 ≤22 s）或改正中断 → 退回 SINGLE【M §2.109 P284】。WAAS：SBAS 改正丢失超过 SBASTIMEOUT（默认 auto）→ 退回【M §2.134 P324】。PROPAGATED：观测恢复 → 回到相应解算状态；外推超时/方差超限 → NONE。OEM7 补充：非 RTK 模式下伪距差分解按 PSRDIFFTIMEOUT 时长维持【M P429】。
典型场景
无任何差分源的独立使用 = SINGLE；接电台/网络 DGPS = PSRDIFF；开阔地带收到 SBAS = WAAS；过立交桥下 1–2 秒丢星但马上恢复 = 可能闪一下 PROPAGATED。

② 浮点类：FLOATCONV(4) / WIDELANE(5) / NARROWLANE(6) / L1_FLOAT(32) / IONOFREE_FLOAT(33) / NARROW_FLOAT(34)

含义
已经在用载波相位（RTK 引擎已启动），但整周模糊度还没解成整数。浮点是通往固定的“收敛走廊”，精度分米级。其中 4/5/6 为 OEM4/OEM6 时代命名（OEM7 v11 已列为预留），32/34 为现行 RTK 引擎命名【M】。
进入条件
收到 RTK 载波相位改正数（基站/网络 RTK），共视卫星数满足要求，模糊度参数开始估计但尚未固定。模糊度固定所需时间取决于 RTK 基线长度、电离层活跃度与其他观测条件【N】。
退出条件
模糊度固定并确认 → 对应的 *_INT 固定解（升级）；RTK 改正中断 → 按 RTKTIMEOUT（默认 60 s，范围 5–60 s）判定失效后退回 PSRDIFF/SINGLE【M §2.129 P316】；低延迟 RTK 在最后一次基站观测后最多外推 60 s 即回退到最佳可用解，精度退化体现在标准差字段【M P429–430】；基线过长或共视星不足 → 在浮点各阶段之间重新收敛。
典型场景
RTK 刚连上改正数的几秒~几十秒；遮挡后重新收敛期间；基线长、电离层活跃时可能长期停在浮点。

③ 固定类：L1_INT(48) / WIDE_INT(49) / NARROW_INT(50) / RTK_DIRECT_INS(51)

含义
整周模糊度成功解为整数并确认——厘米级 RTK 固定解，是测量级应用的目标状态。L1_INT=单频固定；WIDE_INT=宽巷固定；NARROW_INT=窄巷固定（双频 RTK 的最终形态，最常见）；RTK_DIRECT_INS=RTK 滤波器由 INS 滤波器直接初始化而“秒固定”【M P434】。
进入条件
浮点解收敛后模糊度固定并通过确认；或（带 INS 的机型）由 INS 直接初始化（RTK_DIRECT_INS）【M】。
退出条件
周跳、遮挡、多径导致模糊度失效 → 退回浮点类重新收敛；RTKINTEGERCRITERIA：固定解的估计标准差超过门限（默认 TOTAL_STDDEV 1.0）时，被强制按对应浮点解上报（如 NARROW_INT → NARROW_FLOAT）【M §2.120 P302】；RTK 改正数中断超 RTKTIMEOUT（默认 60 s）→ 退回 PSRDIFF/SINGLE【M】；RTK ASSIST 可用 L-Band 改正在中断期间维持 RTK，维持时长由 RTKASSISTTIMEOUT 与订阅限制决定【M §2.117–2.118】；卫星失锁 → NONE。
典型场景
开阔天空 + RTK 链路正常时长期保持 NARROW_INT；这是评估设备性能与干扰影响时最关心的状态（“固定率”）。

④ INS 组合类：INS_SBAS(52) / INS_PSRSP(53) / INS_PSRDIFF(54) / INS_RTKFLOAT(55) / INS_RTKFIXED(56)

含义
GNSS/INS 紧耦合（组合导航）机型输出的解，与纯 GNSS 各档一一对应：INS_PSRSP≈SINGLE、INS_PSRDIFF≈PSRDIFF、INS_SBAS≈WAAS、INS_RTKFLOAT≈浮点、INS_RTKFIXED≈固定。区别是解由组合滤波器输出，惯性参与解算与质量控制。52–56 的描述与 OEM7 v11 完全一致【M P434】。
进入条件
设备为 GNSS/INS 组合型号且组合导航使能、IMU 已对准；之后按 GNSS 增强条件在 52~56 之间升降档，条件与纯 GNSS 对应档位相同。
退出条件
与对应 GNSS 档位相同（改正中断降级、模糊度固定升级）；短时完全丢星时依靠惯导维持输出；INS 功能关闭/故障则回到纯 GNSS 状态族。
典型场景
车载/机载组合导航：隧道、城市峡谷中 INS_RTKFIXED → INS_RTKFLOAT → INS_PSRSP 平滑退化，出遮挡后借惯导快速恢复固定（甚至 RTK_DIRECT_INS 秒固定【M】）。

⑤ PPP 类：PPP_CONVERGING(68) / PPP(69) / PPP_BASIC_CONVERGING(77) / PPP_BASIC(78) 及 INS 组合版(73/74/79/80)

含义
精密单点定位：不依赖本地基站，靠星基（L-Band）或网络播发的精密轨道/钟差改正，全球范围达到厘米~分米级【M P435】。OEM7 v11 记载的服务档：68/69/73/74 对应 TerraStar-C / TerraStar-C PRO / TerraStar-X，77–80 对应 TerraStar-L【M P434–435】；带 INS_PPP 前缀的是组合滤波版本。
进入条件
订购并使能 PPP 服务、接收到 PPP 改正数（L-Band 卫星或网络）→ 先进入 *_CONVERGING 收敛态；精度达到收敛门限 → 转入 PPP/PPP_BASIC 收敛完成态。
退出条件
改正信号中断或长时间遮挡 → 退回 CONVERGING 重新收敛（严重时回到 SINGLE）；PPP 改正龄期超 PPPTIMEOUT（默认 360 s，范围 5–900 s）后不再应用改正，未改正的观测也不用于滤波【M §2.103 P272】；取消 PPP 服务 → 回到普通解算状态族。
典型场景
无基站覆盖的远海、荒漠、精准农业；开阔环境收敛完成后可长期保持 PPP。

⑥ UAL 完好性监控类：OPERATIONAL(70) / WARNING(71) / OUT_OF_BOUNDS(72)

含义
UAL（User Accuracy Level，用户精度等级）监控：不只报位置，还实时判断“这个解可不可信”。OEM7 定义：UAL 是用户自定义的标准差门限，用于判定解的可接受性【M §2.166 P374】。OPERATIONAL=标准差在 operational 门限内；WARNING=超 operational 但在 warning 门限内；OUT_OF_BOUNDS=超出 UAL 极限。
进入条件
用 UALCONTROL 命令启用并设定 operational / warning 门限后，BESTPOS 与 GPGGA 的解类型改由这些门限控制；SETBESTPOSCRITERIA 决定拿哪些标准差与门限比较【M §2.166】。
退出条件
标准差改善则 OPERATIONAL←WARNING←OUT_OF_BOUNDS 逐级恢复，恶化则反向降级；对应 NMEA 质量指示：OPERATIONAL→4、WARNING→5、OUT_OF_BOUNDS→1【M Table 68 P375】。
典型场景
OEM7 记载：农业自动驾驶系统依赖 GPGGA 固定解类型（4），RTK 中断会造成脱开；配合 STEADYLINE + GLIDE 在 RTK 中断时维持固定级精度输出，UALCONTROL 保证所需解类型不中断【M §2.166】。

下图把整张表组织成一台状态机。中间主链是接收机正常工作时的“精度提升路径”（从 NONE 一路到 RTK 固定解）；左侧红色虚线是数据中断时的“降级路径”；右侧三块是与主链平行存在的特殊模式（用户 FIX 固定、PPP 精密单点、INS 组合与 UAL 完好性替换）。所有转移条件均来自 OEM7 v11 手册的官方描述（标注 M 及章节/页码），超时数值均为手册记载的出厂默认值，无任何推测成分。

读图要领：正常情况下接收机沿主链“向上爬”——每爬一级都需要新的数据源（差分改正、载波相位、整周模糊度固定）；任何一级数据源中断，就沿红色虚线“向下滑”，滑到哪一级取决于对应超时命令的设定。右侧的 FIX / PPP / INS / UAL 与主链平行：FIX 由用户命令强制进入；PPP 走独立的收敛路径；INS 与 UAL 则是对主链输出的“包装或替换”，不产生新的物理观测。

10. 常见问题（FAQ）

Q1：为什么我的 RTK 固定解（NARROW_INT 50）突然掉成了浮点（NARROW_FLOAT 34）？

按 OEM7 v11 只有三类官方原因：① 差分链路中断，RTK 数据龄期超过 RTKTIMEOUT（默认 60 s）【M §2.129】；② 低延迟 RTK 对基站观测的外推达到 60 s 上限，BESTPOS 回退到最佳可用解【M §3.14 P430】；③ RTKINTEGERCRITERIA 门限触发——固定解的估计标准差超过门限（默认总标准差 1.0 m，典型如高 DOP 的几何构型），接收机主动把固定解改报为浮点【M §2.120】。排查时先看差分龄期字段，再看标准差字段，即可区分是“断链”还是“质量门限”。

Q2：pos type 显示固定解，但表 4-1 的 sol stat 不是 SOL_COMPUTED，该信哪个？

信 sol stat。表 4-1 是解算过程的诊断（这次解算健不健康），表 4-2 只是报告解的来源类型。sol stat 非 0 说明本次解算存在异常原因（观测量不足、残差过大、协方差超限等），此时 pos type 多为 NONE 或保持上一拍结果，不应作为有效定位使用。

Q3：68/69 和 77/78 都是 PPP，有什么区别？

按 OEM7 v11 Table 74：68/69 对应 TerraStar-C / C PRO / X 服务（收敛中/已收敛），77/78 对应 TerraStar-L 服务（收敛中/已收敛）。北云协议对 68/69/73/74 只写了 TerraStar-C，属描述不全，本文档已按 OEM7 补全。两组在 NMEA GGA 中的映射也不同：77→1、78→2，而 68→2、69→5【M Table 78 P437】。

Q4：为什么 BESTPOS 里会出现 70/71/72 这种不像“定位方法”的值？

因为执行了 UALCONTROL ENABLE。该命令让 BESTPOS/GPGGA 的类型字段不再报告解的来源，而是报告用户自定义精度等级：σ ≤ Operational 限值报 OPERATIONAL(70)，介于两门限之间报 WARNING(71)，超过 Warning 限值报 OUT_OF_BOUNDS(72)。典型应用是农业自动驾驶：转向系统只认 GGA 质量 4（RTK 固定），RTK 中断会导致脱开；配合 STEADYLINE/GLIDE 维持固定级精度、再用 UALCONTROL 保证类型输出不中断【M §2.166 P374–375】。UALCONTROL DISABLE 或 CLEAR 后恢复正常的来源类型。

Q5：北云表里 79/80 的 ASCII 名“INS_PPPP_BASIC*”是不是写错了？

是笔误。OEM7 v11 Table 74 中对应条目为 INS_PPP_BASIC_CONVERGING(79) 与 INS_PPP_BASIC(80)（“PPP”为两个 P）。北云协议写成了三个 P（INS_PPPP_BASIC*）。二进制值 79/80 本身没有问题，仅 ASCII 名多出一个 P，本文档已按 OEM7 修正。

Q6：解析程序要不要处理 4/5/6（FLOATCONV/WIDELANE/NARROWLANE）和 33（IONOFREE_FLOAT）？

建议兼容处理。这四个值在北云协议中有明确定义（均属浮点类解），但 OEM7 v11 Table 74 已将其标注为 Reserved。稳妥做法：按北云定义识别并归入“浮点解”档（与 32/34 同级对待），同时做好 Reserved 兜底——遇到任何未识别值应按“未知/预留”处理而不是当作 NONE。

Q7：PROPAGATED(19) 和 INS 组合解（52–56）有什么区别？

PROPAGATED 是纯 GNSS 卡尔曼滤波在没有新观测时的时间推算（短期外推，无惯性器件参与）；INS_* 是 SPAN 组合导航系统（GNSS+IMU）的输出，有惯性器件持续递推，等级镜像底层 GNSS 解算状态。前者是 GNSS 接收机单机行为，后者需要 SPAN/INS 硬件配置【M Table 74 P434–435；§3.14 P430】。
